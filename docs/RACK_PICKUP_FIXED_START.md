# 固定起点取镊 PPO v2

## 行为

机械臂重置到 `RackPickupConfig.initial_arm_q_rad`，XHand 重置为张开手形。初始关节角与支架位置独立；修改支架配置并重新创建任务，会改变预抓取目标，但不会重算初始关节角。默认关节噪声仍为零。

同一个 84 维观测、9 维残差 PPO 负责六阶段：固定起点移动到预抓取位姿 → 近距离接近 → 夹持 → 上提脱架 → 移离并回 HOME → 稳定交接。回合开始有 0.5 秒物理稳定保持，之后第一阶段接受 PPO 的腕部和手指残差。阶段转换不中断回合，也不替换物体状态。

起点以机器人 URDF 的六个机械臂关节顺序指定，名称同时写入 `task.json`：

```json
"initial_arm_q_rad": [0.883515161, -2.023809282, 2.443558301, -0.320460430, 1.931510518, 1.020332944]
```

默认布局下，腕部初始位置约 `(0.08591, 0.25937, 0.99635)` m，预抓取腕部目标约 `(0.08591, 0.37937, 0.99635)` m。两者相距约 12 cm。位置是环境内仿真世界坐标，关节角是模型值，不是已验证的真机指令。

默认第一阶段沿世界 +Y 接近；控制器对位置和旋转目标做限速跟踪。仍使用局部阻尼逆解，不是通用避障规划器；其他起点和支架布局需要重新验证路径。预抓取目标只在任务初始化时计算，尚不支持运行中实时跟随移动的镊子。

## 第一阶段奖励

令 `d` 为实际腕部到名义预抓取目标的距离，`a` 为现有控制器的朝向误差范数（四元数向量误差 `2 sin(theta/2)`，小角度时近似弧度）。前后两次测量使用同一个名义目标，目标不包含 PPO 残差，也不跨阶段计算差值。

每步的进度奖励为：

```text
position_progress = 8 × (d_before − d_after) / 0.15
angle_progress    = 2 × (a_before − a_after) / 0.50
```

靠近/对齐为正，远离/偏转为负，静止为零。该项是误差变化量，不再乘控制周期。对同一目标往返的未折扣进度和为零；这不是宣称具有折扣 MDP 下策略不变性保证的势函数塑形。前 0.5 秒保持期屏蔽进度奖励。

误差惩罚采用每秒奖励率：

```text
error_rate = −2 × (1 − exp(−d / 0.15))
             −1 × (1 − exp(−a / 0.50))

open_rate = 0.5 × min((手指相对张开目标的 RMS 误差 / 0.08 rad)², 4)

arrival_speed_rate = 0.25 × exp(−(d / 0.03 m)²)
                     × min((机械臂关节速度 RMS / 0.12 rad/s)², 4)
```

合成方式：

```text
reward = position_progress + angle_progress
       + dt × (error_rate − open_rate − arrival_speed_rate
               − 推移镊子惩罚 − 过大夹持力惩罚 − 撞架惩罚
               − 残差幅度/变化惩罚 − 0.2 时间成本)
       + 一次性的阶段推进/失败/超时奖励
```

这样在远处移动也能获得接近进度信号；静止时没有正进度，误差率非正且仍支付时间成本。靠近目标后才重点约束速度，避免惩罚正常接近运动。手指允许有残差，但偏离张开姿态会受罚。位置进度和角度进度的相对权重属于初始设计，正式训练后仍需观察奖励分项与成功率。

第一阶段通过条件：

- 位置误差小于 8 mm，朝向误差范数小于 0.1（约 5.7°）。
- 机械臂关节速度 RMS 小于 0.12 rad/s。
- 手指相对张开目标的 RMS 误差小于 0.08 rad。
- 连续满足至少 0.15 秒，且没有触发物理失败或超时。

通过后沿用一次性 `+5` 阶段奖励。第一阶段超时设为 18 秒，其余阶段仍为 12 秒，整个回合上限 45 秒。物理失败 `−15`，超时 `−5`。其余阶段沿用原奖励结构。

## 输出与训练

`task.json` 增加固定初始关节目标、机械臂关节名称、初始腕部位置及预抓取目标。`training.jsonl` 和评估逐步日志增加目标误差及第一阶段各奖励项，方便区分前进、对齐、手形和减速的贡献。

新任务标识为 `rack_pickup_fixed_start_v2`，旧 v1 模型不兼容。训练命令（仓库根目录执行）：

```bash
bash scripts/train_rack_pickup.sh \
  --out runs/rack_pickup_fixed_pilot_01 \
  --num-envs 8 --iterations 20 --rollout-steps 256 \
  --save-every 5 --learning-rate 0.0001 --std 0.15 \
  --seed 0 --device cuda:0
```

评估并录像：

```bash
bash scripts/train_rack_pickup.sh \
  --out runs/rack_pickup_fixed_pilot_eval_01 \
  --evaluate runs/rack_pickup_fixed_pilot_01/latest.pt \
  --num-envs 1 --eval-episodes 3 --video --device cuda:0
```

当前仍是固定支架的训练配置，没有加入支架位置随机化。固定案例通过不能代表其他布局可达，也不能代表真机容错范围或与原夹物 PPO 连续交接成功。

## 验证记录（2026-10-28）

- 最终默认固定起点的零残差完整案例成功 1/1，18.467 秒。第一阶段约 3.517 秒，位置误差从 0.120 m 降至阶段切换前约 0.00219 m；机器人与支架接触合力全程为零。视频、轨迹、源码归档及结果在 `simulation/runs/rack_pickup_fixed_start_verified_20261028/`；全景/近景各 554 帧完整解码。
- 短程 PPO 更新检查：2 环境、每轮 128 步、2 次迭代，共 512 条样本；84 维观测、9 维动作，策略权重有限且有更新。输出在 `simulation/runs/rack_pickup_fixed_train_check_20261028/`。这不是正式训练完成的策略。
- 保存的新检查点完整确定性评估成功 1/1，18.483 秒，结果在 `simulation/runs/rack_pickup_fixed_checkpoint_eval_20261028/`；该次未录像。基础控制器也能成功，因此此结果不能说明 PPO 带来性能提升。
- 将支架和镊子沿 X 平移 2 cm，初始化检查确认所有初始关节目标及初始腕部位置完全相同，预抓取目标沿 X 平移约 2 cm。`simulation/runs/rack_pickup_fixed_shift_check_20261028/` 是刻意限制为 0.1 秒的初始化检查，以回合超时结束，不能当成该布局的完整取镊成功验证。
- 6 项离线回归检查通过，覆盖原掉落/四元数检查、配置校验、静止无进度、往返进度抵消和步长细分一致性。

最初试验的其他固定起点曾在途中撞架或推偏镊子，已保留对应失败运行作为诊断记录。最终默认值选用了验证通过的 +Y 接近方向；任意改变起点不自动获得路径安全保证。
